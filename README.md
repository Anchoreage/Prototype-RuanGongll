# 论证研习

法律论证标注教学原型，配套 Word 文档记录初版系统用例图和三个核心用例的描述表。fit1 的当前交互流程见下文。

## 直接演示

在 GitHub 仓库中选择 **Code → Download ZIP** 并完整解压，或下载 `deliverables/法律论证标注系统项目原型.zip`。双击解压目录中的 `启动原型.cmd`。电脑需安装 Node.js 22 或更高版本，使用已编译的 `dist` 即可演示，无需安装项目依赖。打开的地址为 http://127.0.0.1:4177/ 。关闭运行窗口可停止服务。

请先完整解压，再运行解压目录内的脚本；不要直接在压缩包预览中双击。启动后保留命令行窗口。如果浏览器没有自动打开，请将窗口中显示的地址复制到浏览器地址栏。

启动失败时窗口会停留并显示 `[ERROR]`：`Node.js was not found` 表示尚未安装或未加入 PATH；`Node.js 22 or later is required` 表示版本过低；`Project files are missing` 表示解压不完整。若提示端口 4177 已使用，请关闭之前的原型运行窗口后重试。

`dist` 已随仓库提交；启动脚本按 Windows CRLF 格式保存，GitHub 下载的 ZIP 同样保留该格式。

## 核心流程

工作台按照课程指南第 8.2 节展示“训练—试标—正式标注—复核修订”四阶段：

1. **训练**：新练习首先显示第 1 阶段的指南学习页，阅读四类命题和五种关系的定义与示例，完成理解确认后才开放标注工作台。教师可以导入 `public/标注指南模板.json` 或课程指南 PDF，核对候选规则后创建新练习。PDF、DOCX、TXT 提取参考正文，须人工确认候选；JSON 导入结构化规则。扫描 PDF 不进行 OCR。
2. **试标**：独立拖选文字、保存命题并尝试建立关系。完成至少一个命题后可进入正式标注。试标结果单独保留，不计入正式标注与学习反馈。
3. **正式标注**：从空白开始，完成命题标注和关系构建。新建命题的选区在切换标签或点击其他区域后仍保持高亮。命题显示编号按原文顺序重排，关系引用稳定 ID。支持 S、A、J、M、I 及嵌套关系，例如 S(M(J(p2,p3),p1),p4)；重复、无效端点和不合法匹配会被阻止。
4. **复核修订**：检查命题边界、标签类型、关系结构，可直接修改标注。修改、撤销或重做标注后，检查确认会重置；三项均确认后才能提交。提交后锁定本次结果，在“学习反馈”查看边界、标签和关系结构差异及解释。

**教师关系裁定**：比较固定示例的两个独立版本，采用一方或输入有效表达式重标。长裁定理由可以先“保存裁定草稿”，切换案例或刷新后恢复。首次定稿后，“申请修改”会创建基于当前版本的修订草稿；填写修改人和修改原因，提交后生成新版本，保留每次定稿、理由、时间、指南版本和双方原始版本。取消修订保留原定稿。导出裁定记录包含全部定稿历史，不包含草稿。

桌面工作台采用约 28% 原文、31% 命题列表、40% 学习助手的栏宽，优先保证操作区空间。较窄窗口将原文放在上方，命题列表和学习助手并排；手机采用纵向布局。刷新后若恢复了后续阶段的草稿，会明确显示恢复说明，可选择“从训练开始新练习”。

## 数据与范围

标注草稿及阶段进度自动保存在当前浏览器；裁定草稿需使用裁定页的保存按钮。刷新后恢复。支持30步撤销与重做、JSON结果导出、指南版本绑定、命题依赖关系清理。字符范围为 UTF-16 的 `[start,end)`。标注导出包含独立的试标记录及复核确认信息；裁定导出使用 `schemaVersion: 2`，每个案例保留 `originalVersions` 和按时间追加的 `versions`。旧版裁定记录会作为 v1 读取，原存储记录保留。清理浏览器存储会清除本机草稿，需保留时请先导出。

原型使用演示角色切换，无真实账户或服务端权限；裁定人、修改人为本机填写的演示信息。“申请修改”创建本地修订草稿，未实现多人审批服务。多人协作、真实独立版本上传与对齐、任务批量分配、新练习语料导入、一致性指标监测、Excel导出未实现。四阶段演示采用同一教学案例，双人独立标注与专家冲突裁决使用固定案例演示。标准答案与裁定案例取自课程指南示例；PDF文件名写v1.2，正文声明v1.1，按正文版本使用。合同及合同解释采用SM-C。

## 开发与构建

需要 Node.js 22+。运行 `npm install`，再运行 `npm run dev`。运行 `npm run build` 更新 `dist`。采用 React + Vite；文件内容只在本机浏览器处理。PDF读取器、DOCX解压库按需加载。

源代码按工作台、指南、论证图、裁定与反馈分组件。配套文档生成脚本在 `tools/build_document.py`，需 Python、python-docx 和 Pillow；文档位于 `deliverables`。

## 验证

运行 `npm test` 验证旧裁定记录迁移、跨案例草稿恢复、追加修订版本、存储失败保护与关系表达式校验；运行 `npm run build` 更新演示产物。
